# A100 training and deployment optimization blueprint

## What constitutes an improvement

Optimize elapsed time to better **certified Full endpoints** on held-out design families. Track seconds per 1,024 accepted or rejected environment steps as a secondary measure. Report accepted moves per second as well. GPU utilization, device memory occupancy and the training loss each answer a different question. An A100 busy enumerating rejected arrangements can have excellent utilization and poor training throughput.

Use a paired baseline and candidate with identical corpus fingerprint, source materials, seed, objectives, hardware, driver, fidelity, model tier and validation cases. Keep cold initialization, warm rollout, overlapping updates, validation/reference search and checkpoint I/O as separate intervals. Include total elapsed time with all of them enabled. Compare at equal environment steps, equal optimizer updates and equal wall time. An algorithm can win one comparison and lose the others.

For correctness, preserve fixed tiers, authored relations, original junctions, dimensional and shape bounds, girdle constraints, manufacturability and the existing final adoption predicate. A certificate must apply to the exact candidate, source and policy being scored. Under uncertainty, take the existing authoritative path. Never convert a residual threshold, a neural gain estimate or a time budget into a meet certificate.

## Implemented in this revision

- Episode fallback keeps the scheduled train position separate from the built design. Recovery persists both. This repairs future coverage, including restored slots. Per-round diagnostics report stepped entries, stepped geometric families and entries supplying fresh replay labels.
- Best weights are selected by completed, certified deployment endpoints. Accelerated training validates the portable model on the host for this decision. This additional pass can increase validation time. Its score is reported separately from the diagnostic rollout. Older scores remain historical data.
- New checkpoints carry the effective sensitivity-probe displacement. The teacher verifies commands against the configured first-successful line search before emitting behavior targets.
- Replay records actual rollout outcomes when a fresh bounded teacher search has no winner. PPO uses the terminal horizon and checks KL before touching Adam.
- Imitation inference can request only action means. Device-gathered imitation mini-batches narrow the tier axis before attention while keeping the sampled order. The nominal prepared-window size uses the actual tier bucket. Stage counters record attention pairs per head and pairs avoided at gather. A completed streaming record holds a compact fresh replay sample only when needed. At a 128-tier cap, each completed unlabelled or reused row releases 211,732 bytes of flat input (4 × (3,781 + 128 × 384)); this is a layout calculation, not measured process RSS.
- The throughput binary accepts the native corpus and can time a held-out validation pass separately.

## Baseline on the native A100 run

From the directory containing the rebuilt CUDA binaries, use an empty output location for each experiment. This example selects the native directory alone, reproduces the reported 27 slots and 1,024 environment steps, and exercises a validation boundary. Fix the mini-batch and update count to the values in the actual comparison run if they differ.

```sh
mkdir -p /notebooks/a100-review/baseline
./pleochroma-trainer-cli \
  --no-update-check --device cuda --mode retarget --algo imitation --tier m \
  --design-dir /notebooks/native-designs --workers 27 --seed 42 --max-tiers 128 \
  --batch-size 1024 --mini-batch 128 --updates-per-round 16 --iterations 6 \
  --label-every 2 --label-memory-mib 4096 --objectives mixed --same-material-frac 0.25 \
  --train-fidelity fast --full-fidelity-frac 0 --max-rejected-steps 8 \
  --validation-every 5 --validation-designs 16 --validation-fidelity fast --objective-sweep \
  --save-every 1 --save-stats /notebooks/a100-review/baseline/stats.json \
  --save-weights /notebooks/a100-review/baseline/model.ckpt.json
```

For a shorter pipeline comparison with a single held-out pass, use a fresh, previously nonexistent output directory:

```sh
./pleochroma-throughput-probe --design-dir /notebooks/native-designs \
  --output /notebooks/a100-review/probe-r1 --device cuda --workers 27 --seed 42 \
  --warmup 1 --iterations 3 --batch-size 1024 --mini-batch 128 \
  --updates-per-round 16 --validation-designs 16
```

The probe has its own learning-rate horizon. Use it for throughput and use the production CLI for learning curves. The last iteration of the training CLI also triggers validation. Retain the live progress, generation manifests, evaluation journals, validation case endpoints and coverage summary. For recovery measurement copy a completed generation into a separate run with the same configuration, interrupt a validation run using the normal stop mechanism, resume and count repeated and newly completed cases. Also measure an interruption during an active case. Record peak resident host/device memory and power/utilization over time along with queue and phase counters. A saturated GPU during validation and an idle GPU during rollout require different remedies.

Use historical numbers to order experiments, never as the control for a new binary. In the supplied v6 iteration 5, 1,024 states produced 898 policy forwards (1.14 real states per call); rollout was 1,623 s and the reported update was 0.51 s. Even removing 0.51 s from 1,623 s would save only 0.031% for that iteration; the update can already overlap. The stalled validation sample completed two of 112 cases after 18,529 s and counted 254.5 billion arrangement triples. Device work and CPU service totals accumulated across workers, so they cannot simply be divided by elapsed time to obtain phase percentages.

## Network, inputs and optimizer

**Input sufficiency and identifiability.** In optimizer mode, identical source and target material blocks `s` enter the first affine layer as `Wₛs + Wₜs = (Wₛ + Wₜ)s`. Adding a matrix `D` to one block and subtracting it from the other leaves every such prediction invariant. With width 1,231 and hidden dimension 64 there are 78,784 redundant first-layer parameter directions on that task. Evaluate folding the two matrices for inference or tying inputs in an explicitly versioned optimizer model. Adam's moment updates and weight decay change under parameter tying, so train an ablation and compare its certified scores. For retargeting, first swap only the source description while holding target, geometry and objective fixed. Measure conditional effects before dropping source information. Preserve custom, anisotropic and genuinely authored values through every transform.

**Representation experiments.** Start with a cache of exactly expanded feature vectors. Then compare spectral basis compression against the full 3,781 global and 384 per-tier input widths. Report wavelength reconstruction error, target/action disagreement, decision reversals at acceptance thresholds and Full gain per family. Include rare material/axis/lighting and size cases. Missing native authoring deserves an explicit coverage count. Do not synthesize authored ground truth to fill a missing stratum. Compare attention with smaller equivariant per-tier pooling and a geometry-aware sparse interaction model. A tier permutation accompanied by its feature/provenance permutation should permute per-tier outputs and preserve scalar outputs. Keep a full-interaction baseline for designs with long-range constraints.

**Teacher and loss.** Keep the finite-difference slopes, verified action, tested failing proposal, bounded oracle gain and Full endpoint gain as distinct quantities. Log their masks and counts separately, including how many zero-gain searches are followed by accepted rollouts. Compare positive `action_samples` with `rejected_action_samples` from the same update. Track positive action agreement, false rejection of useful proposals, calibrated gain error and final Full improvement. A failed search only compares proposals that were actually tried. Compare the rollout-evidence loss to verified-positive-only imitation at equal labels, elapsed time and seed. Try ranking multiple certified proposals using pairwise measured gains before adding a learned proposal selector. A gain head trained on a teacher search answers a different question than the gain of the model's own proposed move; fit and validate the latter explicitly before using it to stop search.

**Optimizer and PPO.** Track effective updates, actual learning rates, gradient norm quantiles, clipping fraction and skipped batches per family and dimension. Cross-check analytic gradients against numerical differences on small fixtures, with all-padding, mixed support, zero-gain and saturated-action cases. Compare Adam schedules and a weight-decay ablation under fixed seeds and wall budgets. For PPO, treat the finite deployed horizon as terminal, bootstrap a live batch boundary, and report pre-update KL, refused updates, entropy, accepted moves and Full endpoint gain. Ablate gamma, clipping and any deliberate extra shaping separately. A low imitation loss, high cosine or a small PPO KL does not establish that a model or optimizer minimizes deployment risk.

## Sizing and rollout decisions

Use the following comparisons to decide whether to change the learning problem itself.

| Question | Paired experiment and interpretation |
|---|---|
| Can the policy express the best feasible direction? | Compare held-out oracle commands with the model before and after squash, tier projection and line search. Break errors down into sign, relative magnitude, clipping, immobile tiers and rejection reason. Fit a small fixed oracle dataset to check capacity separately from online state coverage. A feasible direction can move several tiers together even when every single-coordinate probe fails. Include coupled moves in the candidate-ranking experiment and verify every candidate through the existing gates. |
| Is the sensitivity target well conditioned? | For the same state, compare centered and one-sided secants at several representable probe displacements. Separate true zero slopes from unavailable components and from changes in geometry topology. Report per-component support, median absolute slope and high-percentile gradient contribution. Tune Huber scales or component normalization on training data only, then invert the transformation before combining predicted slopes with physical objective weights. Keep the current physical-unit model as the control. |
| Does learning the Fast objective transfer to Full? | Stratify paired Fast-vs-Full gains by tilt, lighting, material and shape target. Measure the frequency with which an apparently improving Fast move loses its gain at Full. Compare training with a small randomized Full fraction against the same additional wall budget spent on Fast labels. If prioritizing near-ties, also retain an independently sampled Full cohort so its evaluation rate remains interpretable. |
| Is optimizer tuning worth the wall time? | Keep the sampled row IDs and order fixed for a short optimizer comparison. Log gradient signal, clipping, parameters updated, support masks and endpoint improvement at a fixed update budget. Then repeat online to expose state-distribution drift. Compare Adam with and without coupled L2 before adding a separately versioned decoupled-decay or alternate optimizer. Reserve optimizer state migration or reset explicitly for a change in update rule. |
| Will lower precision help the A100? | Try BF16 neural projections and attention only behind a backend-specific experiment. Accumulate sensitive reductions in FP32 and compare policy means, post-projection decisions and adopted Full scores. Exclude directed-rounding proofs, residual certificates and original geometry gates from this precision experiment. Use per-stage device timing to determine whether accelerating matrix products moves the end-to-end result. |
| How should speculative work be scheduled? | Maintain ready queues by stage with a bounded in-flight budget; batch compatible independent cases without a global round barrier. Compare fixed quotas with dynamic admission under matched per-entry opportunity. Assign deterministic RNG before execution and commit in canonical order. Profile queue wait and stragglers under cancellation and resume. Count speculative work thrown away as well as completed useful work. |

1. First freeze model M, mini-batch 128 and the label/validation policy. Compare 1, 9, 27 and 54 rollout slots at a fixed number of environment steps and with comparable CPU availability. Record queue depth, queue age, forward batch size, exact geometry work and accepted steps/s. Discard the first-run compilation sample for warm rates but disclose it in time-to-first-checkpoint.
2. Sweep mini-batch 128, 256 and 512 with the same rollout size, clipping, labelled replay and initial weights. Hold total sampled rows fixed for one comparison and optimizer steps fixed for another. Report the observed number of distinct informative rows: early in a run, a nominal 512-row mini-batch may be limited by available replay. Compare model tiers S/M/L separately. More VRAM does not create labelled states.
3. Start each experiment from the same cold or warm state and repeat across several seeds. Use paired family-level deltas and bootstrap **families**, keeping all seven objective contexts of a family together. Report median and tail wall times, score differences and uncertainty; inspect every certificate failure individually. Do not promote a faster path on a favorable aggregate while a high-tier or rare material stratum regresses materially.
4. Choose a practical minimum effect and tolerated Full-score regression **before** the A/B run. For an example throughput gate, require a reproducible 20% reduction in median end-to-end time at the same validation quality, verify the tail and preserve all certification invariants. The threshold is a decision rule, not a forecast. Retain the reference path and record the change in environment, observation, action, evaluation or objective identity whenever its meaning changes.
